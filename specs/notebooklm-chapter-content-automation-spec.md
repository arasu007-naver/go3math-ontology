# 스펙: 도서 단원별 콘텐츠(개념색인·수학 딕셔너리·플래시카드·퀴즈은행) NotebookLM 생성 자동화

- 문서 버전: v1.2 (2026-10-18, NotebookLM 주소 파라미터화)
- 수행 주체: Claude (브라우저 조작 가능한 에이전트, 예: Claude in Chrome / Computer Use)
- 요청자: 피재성 (Qoolla)

## 1. 목적
쿨라 콘텐츠 관리 앱(`http://localhost:3310`)에서 선택한 도서의 **모든 chapter**에 대해, 4개 콘텐츠 유형의 단원 프롬프트를 NotebookLM에 차례로 입력하고 응답(JSON)을 받아 **색인, 딕셔너리, 플래시카드, 퀴즈가 등록되도록** 한다.

서비스 철학상 이 작업은 교재를 콘텐츠 유형별로 구조화해 조회 경로를 짧게 하고, 이후 교육과정 연결과 라이브 수업에 쓰기 위한 데이터 준비 단계이다.

## 2. 실행 파라미터
작업을 시작할 때 아래 값을 받는다. 필수 값이 하나라도 없으면 시작하지 말고 요청한다.

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `BOOK_TITLE` | 필수 | localhost:3310 도서 목록에서 선택할 도서명 | `수학Ⅰ 개념서` |
| `NOTEBOOKLM_URL` | 필수 | 이 도서 전용 NotebookLM 노트북의 정확한 주소 | `https://notebooklm.google.com/notebook/<노트북ID>` |
| `APP_URL` | 선택 | 콘텐츠 관리 앱 주소 (기본값 `http://localhost:3310`) | `http://localhost:3310` |
| `START_CHAPTER` | 선택 | 이어서 시작할 chapter 번호 (기본값 첫 chapter) | `3` |

NotebookLM 노트북은 도서마다 따로 쓴다. 따라서 Claude는 다른 노트북을 찾거나 고르지 않고, 항상 `NOTEBOOKLM_URL`만 사용한다.

## 3. 사전 조건
1. `http://localhost:3310` 앱이 실행 중이다.
2. 같은 브라우저에서 NotebookLM에 이미 로그인되어 있다. 작업 시작 시 Claude가 `NOTEBOOKLM_URL`을 새 탭으로 열고, 노트북 제목이 도서와 맞는지 확인한다.
3. 클립보드 읽기·쓰기 권한이 허용되어 있다.
4. 브라우저 다운로드가 확인 창 없이 기본 다운로드 폴더에 저장되도록 설정되어 있다.
5. 작업 대상 도서는 `BOOK_TITLE` 파라미터로 정해진다.

## 4. 용어와 화면 요소
| 용어 | 위치 | 설명 |
|---|---|---|
| 이전 입력 도서 목록 | localhost:3310 상단 | 페이지네이션된 도서 목록 |
| Chapters 영역 | 도서 클릭 후 표시 | 해당 도서의 chapter 목록 |
| 콘텐츠 탭 | chapter 클릭 후 아래에 표시 | `개념색인`, `수학 딕셔너리`, `플래시카드`, `퀴즈은행` |
| 프롬프트 열기 | 각 콘텐츠 탭 안의 버튼 | 프롬프트 모달을 연다 |
| 추가 버튼 | 각 콘텐츠 탭 안 (모달을 닫은 뒤) | `색인 추가`, `딕셔너리 추가`, `플래시카드 추가`, `퀴즈 추가`. JSON 파일을 선택해 knowledge graph DB에 등록 |
| 이단원프롬프트복사 | 프롬프트 모달 안의 버튼 | 현재 단원의 프롬프트를 클립보드에 복사 |
| 채팅 입력창 | NotebookLM 노트북 화면 하단 | 프롬프트를 붙여 넣고 전송하는 곳 |

### 4.1 대상 도서
- `BOOK_TITLE` 파라미터 값을 사용한다.
- 도서 목록 페이지네이션을 넘기며 해당 도서를 찾는다. 이름이 정확히 일치하는 도서가 없거나 여러 개면 멈추고 보고한다.

## 5. 처리 순서

### 5.1 전체 루프
```
APP_URL 열기, NOTEBOOKLM_URL을 별도 탭으로 열기
BOOK_TITLE 도서 선택
for chapter in Chapters 영역의 chapter (위에서 아래 순서):
    chapter 클릭
    for 탭 in [개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행]:
        단계 A~F 수행 (§5.2)
    chapter 완료 기록
모든 chapter 완료 후 최종 보고 (§8)
```
콘텐츠 유형 순서는 반드시 **개념색인 → 수학 딕셔너리 → 플래시카드 → 퀴즈은행**이다.

### 5.2 탭 하나에 대한 단계
**A. 프롬프트 복사 (localhost:3310 탭)**
1. 현재 chapter가 선택(강조) 상태인지 확인한다.
2. 해당 콘텐츠 탭을 클릭한다.
3. `프롬프트 열기`를 클릭한다.
4. 모달에서 `이단원프롬프트복사`를 클릭한다.
5. 모달에 보이는 프롬프트 첫 줄과 chapter 제목을 기록해 둔다 (검증용).
6. 모달을 닫는다.

**B. 붙여넣기와 전송 (NotebookLM 탭)**
1. `NOTEBOOKLM_URL` 노트북 탭으로 전환한다. 주소가 `NOTEBOOKLM_URL`과 다르면(다른 노트북으로 이동됨) 그 주소로 다시 연다.
2. 채팅 입력창을 클릭하고 기존 입력 내용이 있으면 지운다.
3. 클립보드 내용을 붙여 넣는다 (macOS `Cmd+V`, Windows `Ctrl+V`).
4. 붙여 넣은 텍스트가 비어 있지 않고, A-5에서 기록한 첫 줄과 일치하는지 확인한다.
5. 전송한다.

**C. 응답 대기**
1. 응답 생성 중 표시(로딩, 생성 중 아이콘)가 사라질 때까지 기다린다.
2. 완료 판정: 응답 끝에 JSON 블록(```json … ```) 또는 생성된 JSON 파일이 보이고, 응답 텍스트가 10초 이상 변하지 않는다.
3. 최대 대기 시간은 5분이다. 넘으면 §7의 타임아웃 처리로 간다.

**D. 응답 검증**
1. 응답에 JSON이 있는지 확인한다.
2. 가능하면 JSON의 파싱 가능 여부와 최상위 구조를 확인한다. 예를 들어 배열이거나 기대한 키가 있는지 본다.
3. 응답이 중간에 끊겼다면 NotebookLM에 "이어서 출력"을 요청하지 말고 §7에 따라 재시도한다.

**E. JSON 다운로드 (NotebookLM 탭)**
1. 응답에 생성된 JSON 파일의 다운로드 버튼(또는 파일 링크)을 클릭한다.
2. 파일이 다운로드 폴더에 저장됐는지 확인하고, 파일명과 저장 시각을 기록한다. 같은 이름이 있어 `(1)` 같은 번호가 붙은 경우, 가장 최근 파일을 사용한다.
3. 가능하면 파일명을 `<도서>_<chapter번호>_<유형>.json`으로 바꿔 혼동을 막는다.

**F. knowledge graph DB 등록 (localhost:3310 탭)**
1. localhost:3310 탭으로 돌아간다. 프롬프트 모달이 열려 있으면 닫는다.
2. 현재 chapter와 콘텐츠 탭이 맞는지 다시 확인한다.
3. 유형에 맞는 추가 버튼을 클릭한다.

   | 콘텐츠 탭 | 클릭할 버튼 |
   |---|---|
   | 개념색인 | `색인 추가` |
   | 수학 딕셔너리 | `딕셔너리 추가` |
   | 플래시카드 | `플래시카드 추가` |
   | 퀴즈은행 | `퀴즈 추가` |

4. 파일 선택 대화상자에서 E단계에서 받은 JSON 파일을 선택한다.
5. 등록 성공 표시(토스트, 목록 갱신 등)를 확인한다. 실패 메시지가 나오면 §7에 따라 처리한다.

## 6. 규칙
1. 한 번에 하나의 프롬프트만 처리한다. 응답 완료 전에는 다음 프롬프트를 붙여 넣지 않는다.
2. 탭 전환 후에는 항상 현재 화면이 기대한 곳인지 확인한다 (chapter 제목, 탭 이름).
3. 클립보드는 매번 새로 복사한 내용만 사용한다. 이전 내용이 재사용되지 않도록 B-4 검증을 반드시 거친다.
4. 데이터 삭제, 기존 등록 덮어쓰기, 노트북 소스 변경은 하지 않는다. 이미 등록된 콘텐츠가 있는 단원과 탭은 건너뛰고 기록한다 (덮어쓰기 여부는 사용자에게 확인).
5. `NOTEBOOKLM_URL` 외의 다른 노트북으로 이동하거나 새 노트북을 만들지 않는다.
6. 로그인이 풀리거나 캡차가 나타나면 즉시 멈추고 사용자에게 알린다.

## 7. 오류 처리
| 상황 | 처리 |
|---|---|
| `프롬프트 열기`나 `이단원프롬프트복사` 버튼이 없음 | 페이지를 새로고침하고 chapter와 탭을 다시 선택한다. 그래도 없으면 해당 탭을 실패로 기록하고 다음 탭으로 진행 |
| 붙여 넣은 내용이 비었거나 불일치 | A단계부터 1회 재시도. 다시 실패하면 중단하고 보고 |
| 응답 5분 초과 또는 오류 메시지 | 같은 프롬프트로 1회 재전송. 다시 실패하면 실패로 기록하고 다음 탭으로 진행 |
| JSON이 없거나 파싱 불가 | 1회 재전송. 다시 실패하면 응답 원문을 저장하고 실패로 기록 |
| `NOTEBOOKLM_URL` 접속 불가(권한 없음, 없는 노트북) | 즉시 중단하고 보고 |
| NotebookLM 사용량 한도 메시지 | 즉시 중단하고 진행 상황을 보고 |
| JSON 다운로드 버튼이 없거나 파일이 저장되지 않음 | 응답의 JSON 블록을 복사해 `<도서>_<chapter번호>_<유형>.json` 파일로 직접 저장한 뒤 F단계 진행. 불가능하면 실패로 기록 |
| 추가 버튼 클릭 후 등록 실패 | 같은 파일로 1회 재시도. 다시 실패하면 오류 메시지와 파일 경로를 기록하고 다음 탭으로 진행 |

## 8. 진행 기록과 최종 보고
매 탭마다 아래 형식으로 진행 로그를 남긴다.

```
[chapter 번호. 제목] [유형] 상태(성공/건너뜀/실패) | 재시도 횟수 | 비고
```

모든 chapter가 끝나면 다음을 보고한다.
1. 도서명, 사용한 `NOTEBOOKLM_URL`, 전체 chapter 수, 처리 시간
2. 유형별 성공·실패·건너뜀 개수 표
3. 실패 항목 목록과 원인, 저장된 JSON 파일 경로
4. 다시 실행할 때 이어서 시작할 위치

## 9. 재개(이어하기)
작업이 중단되면 진행 로그의 마지막 성공 항목 다음부터 시작한다. 다시 실행할 때는 같은 `BOOK_TITLE`과 `NOTEBOOKLM_URL`에 `START_CHAPTER`를 지정한다. 이미 성공한 chapter와 유형은 반복하지 않는다.

## 10. 완료 기준
선택한 도서의 모든 chapter에 대해 4개 유형(개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행)이 localhost:3310에 등록되어 있다. 또는 실패 항목이 이유와 함께 보고되어 있다.

## 11. 확인이 필요한 항목
1. NotebookLM 응답 JSON의 기대 스키마 (유형별 필수 키)
2. 이미 등록된 콘텐츠가 있을 때 건너뛸지 덮어쓸지
