# 스펙: 도서 단원별 콘텐츠 NotebookLM 생성 자동화

- 문서 버전: v1.7 (2026-10-18, JSON 다운로드·DB 등록 단계 제거: 프롬프트 입력과 응답 대기만 수행)
- 수행 주체: Claude (브라우저 조작 에이전트, 예: Claude in Chrome / Computer Use)
- 요청자: 피재성 (Qoolla)
- 대상 콘텐츠: 개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행

## 1. 목적
쿨라 콘텐츠 관리 앱에서 선택한 도서의 **지정 범위(`START_INDEX`~`END_INDEX`) chapter**에 대해 4개 콘텐츠 유형의 단원 프롬프트를 순서대로 복사해 NotebookLM에 입력하고, 응답이 끝나기를 기다린 뒤 다음 프롬프트로 넘어간다.

이 작업의 범위는 **프롬프트 입력과 응답 대기까지**다. NotebookLM이 만든 JSON 파일을 다운로드하거나 knowledge graph DB에 등록하는 일은 이 작업에서 하지 않는다. 결과 파일은 NotebookLM 노트북의 Studio 패널에 남는다.

각 유형의 프롬프트는 **통합 프롬프트 1종**이다. 하나의 프롬프트가 domain `수학 내적`(수학 개념 그 자체)과 `수학 외적`(유래·역사, 교육과정, 학습법, 문제해결 전략, 교수법, 응용·맥락, 태도·역량)을 한 번에 다룬다.

## 2. 실행 파라미터
필수 값이 하나라도 없으면 시작하지 말고 요청한다.

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `BOOK_TITLE` | 필수 | 앱 도서 목록에서 선택할 도서명 (정확히 일치) | `수학Ⅰ 개념서` |
| `NOTEBOOKLM_URL` | 필수 | 이 도서 전용 NotebookLM 노트북 주소 | `https://notebooklm.google.com/notebook/<노트북ID>` |
| `APP_URL` | 선택 | 콘텐츠 관리 앱 주소. 기본값 `http://localhost:3310` | `http://localhost:3310` |
| `START_INDEX` | 선택 | 시작할 항목의 index (Chapters 영역 목록 순번, 포함). 기본값 첫 항목 | `3` |
| `END_INDEX` | 선택 | 마지막으로 처리할 항목의 index (포함). 기본값 마지막 항목 | `5` |

작업 범위는 `START_INDEX` ≤ index ≤ `END_INDEX`이다. `START_INDEX`가 `END_INDEX`보다 크거나, 둘 중 하나가 Chapters 영역에 없는 index이면 시작하지 말고 다시 요청한다.

노트북은 도서마다 따로 쓴다. Claude는 다른 노트북을 찾거나 고르지 않고 항상 `NOTEBOOKLM_URL`만 사용한다.

## 3. 사전 조건
1. `APP_URL` 앱이 실행 중이고 로그인되어 있다.
2. 같은 브라우저에서 NotebookLM에 로그인되어 있다.
3. 클립보드 읽기·쓰기 권한이 허용되어 있다.

## 4. 화면 요소
아래에서 "앱 탭"은 `APP_URL` 탭, "노트북 탭"은 `NOTEBOOKLM_URL` 탭을 뜻한다.

| 요소 | 위치 | 설명 |
|---|---|---|
| 이전 입력 도서 목록 | 앱 탭 상단 | 페이지네이션된 도서 목록 |
| Chapters 영역 | 도서 클릭 후 표시 | 해당 도서의 chapter 목록 |
| 콘텐츠 탭 | chapter 클릭 후 아래에 표시 | `개념색인`, `수학 딕셔너리`, `플래시카드`, `퀴즈은행` |
| `프롬프트 열기` | 각 콘텐츠 탭 안 | 그 탭의 통합 프롬프트 모달을 연다. 모달에 응답 파일명이 보인다 |
| 복사 버튼 | 프롬프트 모달 안 | 현재 단원 프롬프트를 클립보드에 복사 (탭별 이름은 아래 표) |
| 채팅 입력창 | 노트북 탭 하단 | 프롬프트를 붙여 넣고 전송 |

| 콘텐츠 탭 | 복사 버튼 | 응답 파일명 | 프롬프트가 참조하는 앞 단계 결과 |
|---|---|---|---|
| 개념색인 | `이 단원 프롬프트 복사` | `${bookId}-${index}-indices.json` | 없음 (교재 원문) |
| 수학 딕셔너리 | `이 단원 프롬프트 복사` | `${bookId}-${index}-dictionary.json` | `${bookId}-${index}-indices.json` |
| 플래시카드 | `이단원프롬프트복사` | `${bookId}-${index}-flashcards.json` | `${bookId}-${index}-indices.json` |
| 퀴즈은행 | `이단원프롬프트복사` | `${bookId}-${index}-quizzes.json` | `${bookId}-${index}-dictionary.json` |

`${bookId}`는 앱에서 선택한 도서의 id(예: `52`), `${index}`는 Chapters 영역 목록 순번이다. 예: `52-12-indices.json`

## 5. 처리 순서

### 5.1 준비
1. `APP_URL`을 연다.
2. `NOTEBOOKLM_URL`을 새 탭으로 열고, 노트북 제목이 `BOOK_TITLE`과 맞는지 확인한다. 다르면 멈추고 보고한다.
3. 앱 탭에서 도서 목록 페이지를 넘기며 `BOOK_TITLE`과 정확히 일치하는 도서를 찾아 클릭한다. 없거나 여러 개면 멈추고 보고한다.
4. Chapters 영역의 항목 수를 확인하고 `START_INDEX`·`END_INDEX`가 유효한지 검사한다 (§2). 처리할 범위(index와 제목)를 로그에 기록한다.

### 5.2 전체 루프
```
for (index, chapter) in Chapters 영역 (위에서 아래, START_INDEX부터 END_INDEX까지, 양 끝 포함):
    chapter 클릭
    for 유형 in [개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행]:
        앞 단계 결과(§4 표)가 이번 chapter에서 실패했으면 → "실패(선행 실패)"로 기록하고 다음 유형
        단계 A~C 수행 (§5.3)
        진행 로그 기록 (§8)
최종 보고 (§8)
```
유형 순서는 반드시 **개념색인 → 수학 딕셔너리 → 플래시카드 → 퀴즈은행**이다. 뒤 유형의 프롬프트가 앞 유형의 응답(§4 표)을 참조하므로, 한 chapter의 4개 유형은 **같은 NotebookLM 대화 안에서 이어서** 처리한다. chapter 도중에 대화를 새로 시작하지 않는다.

### 5.3 유형 하나에 대한 단계

**A. 프롬프트 복사 (앱 탭)**
1. 현재 chapter가 선택(강조) 상태인지 확인한다.
2. 해당 콘텐츠 탭을 클릭한다.
3. `프롬프트 열기`를 클릭한다.
4. 모달의 응답 파일명이 §4 표와 같은지 확인한다.
5. 모달에서 복사 버튼(§4 표)을 클릭한다.
6. 모달의 프롬프트 첫 줄과 chapter 제목을 기록한다 (B-4 검증용).
7. 모달을 닫는다.

**B. 붙여넣기와 전송 (노트북 탭)**
1. 노트북 탭으로 전환한다. 주소가 `NOTEBOOKLM_URL`과 다르면 그 주소로 다시 연다.
2. 채팅 입력창을 클릭하고 기존 입력을 지운다.
3. 클립보드 내용을 붙여 넣는다 (Windows `Ctrl+V`, macOS `Cmd+V`).
4. 붙여 넣은 텍스트가 비어 있지 않고 A-6의 첫 줄과 일치하는지 확인한다.
5. 전송 버튼이 활성 상태인지 확인하고 전송한다. 전송 후 입력창이 비워졌는지 확인한다.

**C. 응답 대기 (노트북 탭)**
1. 생성 중 표시(`생성 중지` 버튼, 진행 문구 등)가 사라질 때까지 기다린다.
2. 완료 판정: 생성 중 표시가 사라지고, 응답에 JSON 코드 블록이 있으며, 응답 텍스트가 10초 이상 변하지 않는다.
3. 최대 대기 시간은 15분이다. 통합 프롬프트는 두 domain을 한 번에 출력하므로 응답이 길고, 페이지 범위가 넓은 단원의 수학 딕셔너리는 10분 가까이 걸릴 수 있다. 넘으면 §7 타임아웃 처리.
4. 응답이 중간에 끊겼으면 "이어서 출력"을 요청하지 말고 §7에 따라 재전송한다.
5. 완료되면 다음 유형으로 넘어간다. 응답의 JSON이나 Studio 파일은 다운로드하지 않는다.

## 6. 규칙
1. 한 번에 하나의 프롬프트만 처리한다. 응답이 끝나기 전에는 다음 프롬프트를 붙여 넣지 않는다.
2. 탭을 전환할 때마다 현재 화면이 기대한 곳인지(chapter 제목, 탭 이름) 확인한다.
3. 클립보드는 매번 새로 복사한 내용만 쓴다. B-4 검증을 반드시 거친다.
4. JSON 파일 다운로드, 앱의 추가 버튼(`색인 추가` 등)을 통한 DB 등록, 앱 데이터 삭제는 하지 않는다.
5. 노트북 소스 변경, Studio 파일 삭제·이름 변경은 하지 않는다. 같은 응답 파일이 Studio에 여러 개 생겨도 그대로 둔다.
6. `NOTEBOOKLM_URL` 외의 노트북으로 이동하거나 새 노트북을 만들지 않는다.
7. 로그인이 풀리거나 캡차가 나타나면 즉시 멈추고 사용자에게 알린다.

## 7. 오류 처리
재시도는 모두 **1회**까지다.

| 상황 | 처리 | 재시도도 실패하면 |
|---|---|---|
| `프롬프트 열기`/복사 버튼 없음 | 새로고침 후 chapter와 탭 다시 선택 | 실패 기록, 다음 유형 |
| 붙여 넣은 내용이 비었거나 불일치 | A단계부터 재시도 | **작업 중단**, 보고 |
| 전송 버튼이 비활성 (프롬프트가 입력 길이 제한 초과) | 재시도 없음. 입력창을 비운다 | 실패 기록(길이 초과, 글자 수 포함), 다음 유형 |
| 응답 15분 초과 또는 오류 메시지 | 같은 프롬프트 재전송 | 실패 기록, 다음 유형 |
| 응답에 JSON 코드 블록 없음 / 응답이 중간에 끊김 | 같은 프롬프트 재전송 | 실패 기록, 다음 유형 |
| 앞 단계 결과가 실패 (§4 표) | 재시도 없음 | "실패(선행 실패)" 기록, 다음 유형 |
| `NOTEBOOKLM_URL` 접속 불가 (권한 없음, 없는 노트북) | 재시도 없음 | **즉시 중단**, 보고 |
| NotebookLM 사용량 한도 메시지 | 재시도 없음 | **즉시 중단**, 진행 상황 보고 |

## 8. 진행 기록과 최종 보고
유형마다 진행 로그를 남긴다.

```
[index. 제목] [유형] 상태(성공/실패) | 재시도 횟수 | 응답 소요 시간 | 비고
```

작업이 끝나거나 중단되면 다음을 보고한다.
1. 도서명, 사용한 `NOTEBOOKLM_URL`, 처리 범위(`START_INDEX`~`END_INDEX`)와 그 chapter 수, 처리 시간
2. 유형별 성공·실패 개수 표
3. 실패 항목과 원인
4. 다시 실행할 때 지정할 `START_INDEX`와 `END_INDEX`

## 9. 재개
같은 `BOOK_TITLE`, `NOTEBOOKLM_URL`로 다시 실행한다. `START_INDEX`는 4개 유형을 모두 마치지 못한 첫 chapter의 index로, `END_INDEX`는 처음 실행 때와 같은 값으로 지정한다. 재개한 chapter는 뒤 유형이 앞 유형의 응답을 참조하므로 개념색인부터 4개 유형을 다시 처리한다.

## 10. 완료 기준
선택한 도서의 `START_INDEX`~`END_INDEX` 범위 chapter 모두에 대해 4개 유형의 프롬프트가 NotebookLM에 입력되어 응답이 완료되었거나, 완료되지 않은 항목이 이유와 함께 보고되어 있다.
