# 스펙: 도서 단원별 콘텐츠 NotebookLM 생성 자동화

- 문서 버전: v1.6 (2026-10-18, END_INDEX 추가: START_INDEX~END_INDEX 범위 처리)
- 수행 주체: Claude (브라우저 조작 에이전트, 예: Claude in Chrome / Computer Use)
- 요청자: 피재성 (Qoolla)
- 대상 콘텐츠: 개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행

## 1. 목적
쿨라 콘텐츠 관리 앱에서 선택한 도서의 **지정 범위(`START_INDEX`~`END_INDEX`) chapter**에 대해 4개 콘텐츠 유형의 단원 프롬프트를 NotebookLM에 차례로 입력하고, 응답 JSON을 앱에 등록한다.

각 유형의 프롬프트는 **통합 프롬프트 1종**이다. 하나의 프롬프트가 domain `수학 내적`(수학 개념 그 자체)과 `수학 외적`(유래·역사, 교육과정, 학습법, 문제해결 전략, 교수법, 응용·맥락, 태도·역량)을 한 번에 다루고, 응답의 모든 항목에 `domain` 필드가 붙는다. 수학/메타 프롬프트를 따로 고르는 단계는 없다.

이 작업은 교재를 콘텐츠 유형별로 구조화해 조회 경로를 짧게 하고, 이후 교육과정 연결과 라이브 수업에 쓸 데이터를 준비하는 단계이다.

## 2. 실행 파라미터
필수 값이 하나라도 없으면 시작하지 말고 요청한다.

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `BOOK_TITLE` | 필수 | 앱 도서 목록에서 선택할 도서명 (정확히 일치) | `수학Ⅰ 개념서` |
| `NOTEBOOKLM_URL` | 필수 | 이 도서 전용 NotebookLM 노트북 주소 | `https://notebooklm.google.com/notebook/<노트북ID>` |
| `APP_URL` | 선택 | 콘텐츠 관리 앱 주소. 기본값 `http://localhost:3310` | `http://localhost:3310` |
| `START_INDEX` | 선택 | 시작할 항목의 index (Chapters 영역 목록 순번, 포함). 기본값 첫 항목 | `3` |
| `END_INDEX` | 선택 | 마지막으로 처리할 항목의 index (포함). 기본값 마지막 항목 | `5` |

작업 범위는 `START_INDEX` ≤ index ≤ `END_INDEX`이다. `START_INDEX`가 `END_INDEX`보다 크거나, 둘 중 하나가 Chapters 영역에 없는 index이면 시작하지 말고 다시 요청한다.

노트북은 도서마다 따로 쓴다. Claude는 다른 노트북을 찾거나 고르지 않고 항상 `NOTEBOOKLM_URL`만 사용한다.

## 3. 사전 조건
1. `APP_URL` 앱이 실행 중이다.
2. 같은 브라우저에서 NotebookLM에 로그인되어 있다.
3. 클립보드 읽기·쓰기 권한이 허용되어 있다.
4. 브라우저 다운로드가 확인 창 없이 기본 다운로드 폴더에 저장되도록 설정되어 있다.

## 4. 화면 요소
아래에서 "앱 탭"은 `APP_URL` 탭, "노트북 탭"은 `NOTEBOOKLM_URL` 탭을 뜻한다.

| 요소 | 위치 | 설명 |
|---|---|---|
| 이전 입력 도서 목록 | 앱 탭 상단 | 페이지네이션된 도서 목록 |
| Chapters 영역 | 도서 클릭 후 표시 | 해당 도서의 chapter 목록 |
| 콘텐츠 탭 | chapter 클릭 후 아래에 표시 | `개념색인`, `수학 딕셔너리`, `플래시카드`, `퀴즈은행` |
| `프롬프트 열기` | 각 콘텐츠 탭 안 | 그 탭의 통합 프롬프트 모달을 연다. 모달에 `domain: 수학 내적 + 수학 외적` 표시와 다운로드 파일명이 보인다 |
| 복사 버튼 | 프롬프트 모달 안 | 현재 단원 프롬프트를 클립보드에 복사 (탭별 이름은 아래 표) |
| 추가 버튼 | 각 콘텐츠 탭 안 | JSON 파일을 선택해 knowledge graph DB에 등록 (아래 표) |
| 채팅 입력창 | 노트북 탭 하단 | 프롬프트를 붙여 넣고 전송 |

| 콘텐츠 탭 | 복사 버튼 | 응답 파일명 | 입력으로 쓰는 앞 단계 결과 | 추가 버튼 |
|---|---|---|---|---|
| 개념색인 | `이 단원 프롬프트 복사` | `${index}-indices.json` | 없음 (교재 원문) | `색인 추가` |
| 수학 딕셔너리 | `이 단원 프롬프트 복사` | `${index}-dictionary.json` | `${index}-indices.json` | `딕셔너리 추가` |
| 플래시카드 | `이단원프롬프트복사` | `${index}-flashcards.json` | `${index}-indices.json` | `플래시카드 추가` |
| 퀴즈은행 | `이단원프롬프트복사` | `${index}-quizzes.json` | `${index}-dictionary.json` | `퀴즈 추가` |

`${index}`는 Chapters 영역 목록 순번이다.

## 5. 처리 순서

### 5.1 준비
1. `APP_URL`을 연다.
2. `NOTEBOOKLM_URL`을 새 탭으로 열고, 노트북 제목이 `BOOK_TITLE`과 맞는지 확인한다.
3. 앱 탭에서 도서 목록 페이지를 넘기며 `BOOK_TITLE`과 정확히 일치하는 도서를 찾아 클릭한다. 없거나 여러 개면 멈추고 보고한다.
4. Chapters 영역의 항목 수를 확인하고 `START_INDEX`·`END_INDEX`가 유효한지 검사한다 (§2). 처리할 범위(index와 제목)를 로그에 기록한다.

### 5.2 전체 루프
```
for (index, chapter) in Chapters 영역 (위에서 아래, START_INDEX부터 END_INDEX까지, 양 끝 포함):
    chapter 클릭
    for 유형 in [개념색인, 수학 딕셔너리, 플래시카드, 퀴즈은행]:
        이미 등록된 콘텐츠가 있으면 → 건너뜀으로 기록하고 다음 유형
        앞 단계 결과(§4 표)가 이번 chapter에서 실패했으면 → "실패(선행 실패)"로 기록하고 다음 유형
        단계 A~F 수행 (§5.3)
        진행 로그 기록 (§8)
최종 보고 (§8)
```
유형 순서는 반드시 **개념색인 → 수학 딕셔너리 → 플래시카드 → 퀴즈은행**이다. 뒤 유형의 프롬프트가 앞 유형의 응답 파일(§4 표)을 참조하므로, 한 chapter의 4개 유형은 **같은 NotebookLM 대화 안에서 이어서** 처리한다. chapter 도중에 대화를 새로 시작하지 않는다.

### 5.3 유형 하나에 대한 단계

**A. 프롬프트 복사 (앱 탭)**
1. 현재 chapter가 선택(강조) 상태인지 확인한다.
2. 해당 콘텐츠 탭을 클릭한다.
3. `프롬프트 열기`를 클릭한다.
4. 모달의 다운로드 파일명이 §4 표의 응답 파일명과 같은지 확인한다.
5. 모달에서 복사 버튼(§4 표)을 클릭한다.
6. 모달의 프롬프트 첫 줄과 chapter 제목을 기록한다 (B-4 검증용).
7. 모달을 닫는다.

**B. 붙여넣기와 전송 (노트북 탭)**
1. 노트북 탭으로 전환한다. 주소가 `NOTEBOOKLM_URL`과 다르면 그 주소로 다시 연다.
2. 채팅 입력창을 클릭하고 기존 입력을 지운다.
3. 클립보드 내용을 붙여 넣는다 (Windows `Ctrl+V`, macOS `Cmd+V`).
4. 붙여 넣은 텍스트가 비어 있지 않고 A-6의 첫 줄과 일치하는지 확인한다.
5. 전송한다.

**C. 응답 대기**
1. 생성 중 표시(로딩 아이콘 등)가 사라질 때까지 기다린다.
2. 완료 판정: 응답 끝에 JSON 블록(```json … ```) 또는 생성된 JSON 파일이 보이고, 응답 텍스트가 10초 이상 변하지 않는다.
3. 최대 5분. 넘으면 §7 타임아웃 처리. 통합 프롬프트는 두 domain을 한 번에 출력하므로 응답이 길다. 특히 퀴즈은행(2벌 구성)은 대기 시간이 길 수 있다.

**D. 응답 검증**
1. 응답에 JSON이 있는지 확인한다.
2. 가능하면 파싱해서 §5.4 기준을 확인한다.
3. 응답이 중간에 끊겼으면 "이어서 출력"을 요청하지 말고 §7에 따라 재전송한다.

**E. JSON 다운로드 (노트북 탭)**
1. 응답의 JSON 파일 다운로드 버튼(또는 파일 링크)을 클릭한다.
2. 다운로드 폴더에 저장됐는지 확인하고 파일명과 저장 시각을 기록한다. 파일명은 §4 표의 응답 파일명이어야 한다.
3. 같은 이름이 있어 `(1)` 같은 번호가 붙었으면 가장 최근 파일을 쓴다. 응답 파일명은 도서와 관계없이 `${index}-<유형>.json`으로 같으므로, 진행 로그에 도서명과 함께 경로를 남긴다.

**F. 등록 (앱 탭)**
1. 앱 탭으로 돌아간다.
2. 현재 chapter와 콘텐츠 탭이 맞는지 다시 확인한다.
3. 유형에 맞는 추가 버튼(§4 표)을 클릭한다.
4. 파일 선택 대화상자에서 E단계의 JSON 파일을 선택한다.
5. 등록 성공 표시(토스트, 목록 갱신 등)를 확인한다. 실패하면 §7.

### 5.4 응답 JSON 검증 기준
1. 최상위가 배열이다. (개념색인은 빈 배열이 아니어야 한다.)
2. 모든 항목에 `chapter_title`, `domain`, `category`, `pages`가 있다.
3. `domain`은 `"수학 내적"` 또는 `"수학 외적"` 중 하나다.
4. 유형별 필수 키가 있다.

| 유형 | 공통 필수 키 | `수학 내적` 전용 | `수학 외적` 전용 |
|---|---|---|---|
| 개념색인 | `term`, `definition` | `formula` | `scope`, `related_math_terms`, `evidence` |
| 수학 딕셔너리 | `term`, `english_term`, `definition`, `misconceptions`, `examples` | `geometric_meaning`, `theorems`, `prerequisites`, `subsequent_concepts` | `scope`, `background`, `educational_significance`, `application`, `related_math_terms`, `related_meta_terms`, `evidence` |
| 플래시카드 | `front`, `back`, `hint` | `formula` | `scope`, `related_math_terms` |
| 퀴즈은행 | `quiz_type`, `question`, `explanation`, `socratic_hints` (3개) | — | `scope`, `related_math_terms` |

- 퀴즈은행의 `quiz_type`이 `"multiple_choice"`이면 `options`(4개)와 `correct_option_id`(1~4)가 있어야 한다.
- 수학 딕셔너리의 `examples`는 domain에 따라 형태가 다르다. `수학 내적`은 `{problem, solution}`, `수학 외적`은 `{situation, description}`이다.

## 6. 규칙
1. 한 번에 하나의 프롬프트만 처리한다. 응답이 끝나기 전에는 다음 프롬프트를 붙여 넣지 않는다.
2. 탭을 전환할 때마다 현재 화면이 기대한 곳인지(chapter 제목, 탭 이름) 확인한다.
3. 클립보드는 매번 새로 복사한 내용만 쓴다. B-4 검증을 반드시 거친다.
4. 데이터 삭제, 기존 등록 덮어쓰기, 노트북 소스 변경은 하지 않는다. 이미 등록된 콘텐츠는 건너뛰고 기록한다.
5. `NOTEBOOKLM_URL` 외의 노트북으로 이동하거나 새 노트북을 만들지 않는다.
6. 로그인이 풀리거나 캡차가 나타나면 즉시 멈추고 사용자에게 알린다.
7. 응답의 `domain` 값을 Claude가 고치거나 재분류하지 않는다. 기준에 맞지 않으면 §7에 따라 재전송한다.

## 7. 오류 처리
재시도는 모두 **1회**까지다.

| 상황 | 처리 | 재시도도 실패하면 |
|---|---|---|
| `프롬프트 열기`/복사 버튼 없음 | 새로고침 후 chapter와 탭 다시 선택 | 실패 기록, 다음 유형 |
| 붙여 넣은 내용이 비었거나 불일치 | A단계부터 재시도 | **작업 중단**, 보고 |
| 응답 5분 초과 또는 오류 메시지 | 같은 프롬프트 재전송 | 실패 기록, 다음 유형 |
| JSON 없음, 파싱 불가, 또는 §5.4 기준 불충족 (`domain` 누락·잘못된 값 포함) | 같은 프롬프트 재전송 | 응답 원문 저장, 실패 기록, 다음 유형 |
| JSON 다운로드 버튼 없음 / 파일 미저장 | 응답 JSON 블록을 복사해 §4 표의 응답 파일명으로 직접 저장 후 F단계 | 실패 기록, 다음 유형 |
| 추가 버튼 클릭 후 등록 실패 | 같은 파일로 재시도 | 오류 메시지·파일 경로 기록, 다음 유형 |
| 앞 단계 결과가 실패 (§4 표) | 재시도 없음 | "실패(선행 실패)" 기록, 다음 유형 |
| `NOTEBOOKLM_URL` 접속 불가 (권한 없음, 없는 노트북) | 재시도 없음 | **즉시 중단**, 보고 |
| NotebookLM 사용량 한도 메시지 | 재시도 없음 | **즉시 중단**, 진행 상황 보고 |

## 8. 진행 기록과 최종 보고
유형마다 진행 로그를 남긴다.

```
[index. 제목] [유형] 상태(성공/건너뜀/실패) | 재시도 횟수 | 수학 내적 n건 · 수학 외적 m건 | 비고
```

작업이 끝나거나 중단되면 다음을 보고한다.
1. 도서명, 사용한 `NOTEBOOKLM_URL`, 처리 범위(`START_INDEX`~`END_INDEX`)와 그 chapter 수, 처리 시간
2. 유형별 성공·실패·건너뜀 개수 표, 그리고 유형별 `수학 내적`·`수학 외적` 항목 수 합계
3. 실패 항목, 원인, 저장된 JSON 파일 경로
4. 다시 실행할 때 지정할 `START_INDEX`와 `END_INDEX`

## 9. 재개
같은 `BOOK_TITLE`, `NOTEBOOKLM_URL`로 다시 실행한다. `START_INDEX`는 진행 로그의 마지막 성공 항목의 index로, `END_INDEX`는 처음 실행 때와 같은 값으로 지정한다. 이미 등록된 유형은 §5.2의 건너뜀 규칙으로 반복되지 않는다.

## 10. 완료 기준
선택한 도서의 `START_INDEX`~`END_INDEX` 범위 chapter 모두에 대해 4개 유형이 앱에 등록되어 있거나, 등록되지 않은 항목이 이유와 함께 보고되어 있다.

## 11. 확인이 필요한 항목
1. 이미 등록된 콘텐츠가 있을 때의 정책. 현재 기본값은 건너뛰기이며, 덮어쓰기가 필요하면 사용자 확인 후 진행
2. 재개 시 앞 단계가 "건너뜀"(이미 등록)인 경우, 뒤 단계 프롬프트가 참조할 앞 단계 응답 파일이 NotebookLM 대화에 없다. 이때 앞 단계를 다시 생성할지(등록은 하지 않음), 앞 단계 JSON 파일을 대화에 첨부할지 결정 필요
3. 현재 앱의 등록 처리(DB)는 `domain`과 `수학 외적` 전용 필드를 저장하지 않는다. DB 반영 전까지는 등록 성공이어도 이 필드들은 DB에 남지 않는다
