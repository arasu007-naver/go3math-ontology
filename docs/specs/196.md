# exam2concepts(e2c) — 기출문제 → 단원 1개 → 개념 연동 (v1.1)

상세 원문: **exam_problems2concepts** `specs/exam_problems2concepts.md`(이 카드와 같은 v1.1). 아래에 적지 않은 세부는 원문을 그대로 따릅니다. 프롬프트 문구 §11, JSON 스키마 §10, 비용 §15, 리포트 형식 §21이 여기에 해당합니다. 이 문서와 원문이 다르면 **이 문서가 우선**합니다. 다른 부분은 대부분 기존 코드에 맞춘 경로·환경변수·테스트 도구입니다.

## 배경과 목적
- MariaDB 기출문제 약 7,142문항(읽기 전용)마다 KG 2022 개정 교육과정의 단원 정확히 1개, 그 단원 안의 주 개념 1개, 보조 개념 0~3개를 정합니다.
- 결정 순서: JEV·Claude·Gemini가 관련 단원 집합을 냅니다. 코드가 모델마다 `pickFinalUnit`(선후상 가장 뒤 단원)을 적용해 모델당 1표를 만듭니다. 2표 이상 일치하면 채택하고, 아니면 Grok이 정합니다. 이어서 채택 단원의 개념만 후보로 두고 세 모델이 주 1개와 보조 0~3개를 냅니다. 주 개념이 2표 이상 일치하면 채택하고, 아니면 Grok이 정합니다.
- 검증 사유 코드로 `auto`와 `needs_review`를 나눕니다. 검토 UI에서 수동으로 고칠 수 있고, 수정 이력이 남으며, 재실행해도 수정값을 덮어쓰지 않습니다.
- 위치는 같은 앱 `web/`입니다. 기존 **Legacy2OntologyPage** `web/src/app/legacy2ontology/page.tsx`, **Legacy2OntologyClient** `web/src/components/l2o/Legacy2OntologyClient.tsx`와 나란히 둡니다.

## 범위
### 하는 것
1. 스키마 조사 결과를 `docs/e2c-schema.md`에 적고, 원문 §2의 placeholder 전부를 실제 이름으로 바꿔 `web/src/lib/e2c/schema-names.ts` 한 곳에만 상수로 둡니다. 시험 과목 → KG 과목 매핑도 적습니다. JEV 명세는 `docs/jev-api.md`에 적습니다.
2. DDL `web/db/e2c-schema.sql`(원문 §12 테이블, 여러 번 실행해도 안전), 적용 스크립트 `web/scripts/db-setup-e2c.mjs`(`web/scripts/db-setup-l2o.mjs`와 같은 방식), npm script `db:e2c`를 추가합니다.
3. 전처리(원문 §4), 후보 단원 축소(§5.1), 개념 options(§7.1)를 구현합니다.
4. 어댑터: `web/src/lib/e2c/adapters/{types,jev,claude,gemini,grok}.ts`(원문 §9 인터페이스).
5. 순수 함수: `web/src/lib/e2c/precedence.ts`(`pickFinalUnit`), `web/src/lib/e2c/vote.ts`(`tallyUnits`, `tallyConcepts`), `web/src/lib/e2c/review.ts`(사유 코드, §8), `web/src/lib/e2c/hash.ts`.
6. 파이프라인 `web/src/lib/server/e2cPipeline.ts`와 job 러너 `web/src/lib/server/e2cJobs.ts`(realtime + batch W1~W4).
7. API 라우트 `web/src/app/api/e2c/**`.
8. 페이지 **Exam2ConceptsPage** `web/src/app/exam2concepts/page.tsx`와 컴포넌트 **Exam2ConceptsClient** `web/src/components/e2c/Exam2ConceptsClient.tsx`(필요하면 `web/src/components/e2c/` 아래 하위 컴포넌트).
9. 파일럿 라벨 입력과 리포트 생성: `reports/e2c-<kind>-<date>.md`를 만듭니다. 파일럿 리포트에는 원문 §17 지표를 넣습니다.
10. `web/.env.example`에 변수 이름만 추가합니다.
11. `docs/COMPONENTS.md`에 새 페이지·컴포넌트·서버 모듈·유틸·DDL·문서를 등록합니다(CLAUDE.md 갱신 규칙).
### 하지 않는 것
- MariaDB 쓰기, 스키마 변경, 문제·해답 본문 수정.
- KG 최종 반영(`applied` 버튼과 트랜잭션), `<<KG_PROBLEM_LINK>>` 생성. 원문 구현 순서 §19의 10번은 사용자 승인 후 별도 카드로 합니다. 조사 결과만 `docs/e2c-schema.md`의 Open Question에 남깁니다.
- 실제 유료 API로 파일럿이나 전체 실행 수행, 배포, push, 운영 DB 반영.
- 개념 간 선후 작업, 단원·과목 선후 편집, `specs/math_concepts2ontology.md` 변경, legacy2ontology 동작 변경.
- Playwright·msw 같은 새 테스트 프레임워크 도입. 기존 `node --test` 방식을 씁니다.

## 변경할 동작
### 기존 코드 재사용(필수)
- MariaDB: **legacyDb** `web/src/lib/server/legacyDb.ts`와 같은 방식(풀 연결마다 `SET SESSION TRANSACTION READ ONLY`, SELECT만, 조회 함수만 export)으로 `web/src/lib/server/e2cLegacyDb.ts`를 둡니다. HTML 제거는 `stripHtml`을 재사용합니다.
- KG 연결: **l2oPool** `web/src/lib/server/l2oPool.ts`의 `pool`을 재사용합니다.
- 단원 목록: **l2oUnits** `web/src/lib/server/l2oUnits.ts`의 `listUnits`를 씁니다. 고등 단원은 `kg.nodes` level 노드 `L4-H*`(category=대단원)입니다.
- 선후 그래프: `kg.edges` 타입 `PREREQUISITE_OF`(단원 A→B = A가 B의 선수)와 `PREREQ_OF`(과목 A→B)입니다. 원문 §5.3대로 과목 선후를 단원 선후에 포함합니다. 방향은 조사에서 실제로 확인해 `docs/e2c-schema.md`에 적습니다.
- 개념과 개념→단원: `kg.math_concepts`, `kg.concept_unit_edges`(`is_active=true`). legacy→대표 개념 경로: `l2o.dedupe_member` → `l2o.migration_result.kg_concept_id`.
- 임베딩: **embedding** `web/src/lib/server/embedding.ts`의 `embedTexts`, 유사도는 **l2oDedupeUtil** `web/src/lib/l2o/dedupe.ts`의 `cosine`을 씁니다.
- HTTP 재시도와 POST: **selectorCommon** `web/src/lib/server/selectors/common.ts`의 `postJson`, `HttpError`, `errorText`를 재사용합니다. e2c 재시도는 원문 §9(1s→2s→4s→8s, 최대 5회, Retry-After 우선)라서 e2c 전용 `withRetry` 변형을 `web/src/lib/e2c/retry.ts`에 둡니다. 기존 `withRetry`(3회)는 바꾸지 않습니다.
- Claude: **claudeSelector** `web/src/lib/server/selectors/claude.ts`와 같은 호출 방식을 씁니다. `@anthropic-ai/sdk` beta messages, `output_config.format` json_schema(후보 enum 주입), `effort: low`, server-side fallback을 쓰고 **temperature는 보내지 않습니다**(현재 모델이 400을 냄). max_tokens는 2000이고 refusal은 실패로 처리합니다.
- Gemini: **geminiSelector** `web/src/lib/server/selectors/gemini.ts` 방식(generateContent, `temperature: 0`, `responseMimeType: application/json` + `responseSchema`)을 씁니다.
- JEV: **jevSelector** `web/src/lib/server/selectors/jev.ts`에 이미 쓰이는 TypeSafe System One `POST {JEV_API_URL}`(기본 `https://api.typesafe.ai/v1/systemone`)을 씁니다. 요청은 `{model, state, questions:{q:{type:'choice', instructions, criteria:{id:text}}}}`이고 응답은 `answers.q.{choice, confidence, probabilities}`입니다. 다른 엔드포인트는 만들지 않습니다. 키가 없으면 `error='not_configured'`입니다.
- Grok: xAI `https://api.x.ai/v1/chat/completions`, `response_format: {type:'json_schema'}`, `reasoning_effort`를 씁니다. 비용은 `usage.cost_in_usd_ticks × 1e-10`입니다. Batch는 xAI Batch API를 쓰고 `batch_request_id = problemId:stage:promptVersion`입니다.
- 수식 렌더는 **MathView** `web/src/components/MathView.tsx`(KaTeX)를 재사용합니다. 원문의 MathJax 언급은 이것으로 대체합니다. job 진행 표시는 **JobProgress** `web/src/components/l2o/JobProgress.tsx`의 패턴을 따릅니다. 인증은 legacy2ontology 페이지·API와 같은 세션 가드를 씁니다.

### 파이프라인 규칙(원문 그대로, 요점)
- 전처리 §4
  - `keySteps`는 해답을 코드로 문장·줄 단위로 나눠 S1..Sn을 붙입니다.
  - 문제+해답이 40자 미만이면 `skipped_no_text`입니다.
  - 6,000자를 넘으면 중략 표시 후 자르고 `truncated=true`로 둡니다.
  - `inputHash = sha256(problemText+solutionText+meta)`입니다.
  - 대표 개념으로 재매핑하지 못한 legacy 힌트는 버리고 개수만 기록합니다.
- 후보 단원 §5.1
  - 과목 매핑으로 거르고, legacy 힌트 단원은 반드시 넣습니다.
  - 15개를 넘으면 임베딩 상위 15개 + 힌트 단원입니다.
  - 0개면 고등 전체 단원으로 넓히고 `candidate_fallback=true`입니다.
  - 세 모델은 같은 목록을 받고, 후보 0개면 호출하지 않습니다.
- `pickFinalUnit(unitIds, graph)`
  - 전이 폐쇄에서 최대 원소가 1개면 `rule='precedence'`입니다.
  - 최대 원소가 여러 개면 교육과정 순서(과목 순서, 단원 번호)상 가장 뒤 단원이고 `rule='curriculum_order'`입니다.
  - 사이클이면 `error='precedence_cycle'`입니다.
  - 모델을 호출하지 않는 결정적 함수입니다.
- JEV 임계값: 관련 단원은 확률 ≥ `jev_unit_min_prob`(0.10)이고, 없으면 최고 확률 1개입니다. 보조 개념은 확률 ≥ `jev_secondary_min_prob`(0.15)인 다음 순위로 최대 3개입니다.
- `tallyUnits` / `tallyConcepts`: 원문 §6.1 표와 §7.3을 따릅니다.
  - 성공 모델 3개: 2표 이상 일치 → majority, 아니면 Grok.
  - 성공 모델 2개: 일치 → majority + `two_models_only`, 불일치 → Grok.
  - 성공 모델 1개: Grok + `insufficient_models`.
  - 성공 모델 0개: `error`, Grok 호출 안 함.
  - 보조 개념 규칙: 채택 주 개념을 빼고, 역할과 관계없이 2개 이상 모델이 제안한 개념입니다. (제안 모델 수 desc, 평균 확신도 desc, conceptId asc) 순 상위 3개이고, 성공 모델이 2개면 두 모델 모두 제안한 개념입니다.
  - 파라미터는 `e2c.config`에 둡니다.
- Grok
  - 단원: 성공 모델의 관련 단원 합집합 안에서 `usedUnits`를 받고, 코드가 `pickFinalUnit`을 적용합니다.
  - 개념: 성공 모델이 제안한 모든 개념의 합집합 안에서 주 1개 + 보조 ≤3개를 받습니다.
  - 성공 모델이 1개면 범위를 후보·options 전체로 넓힙니다.
  - 범위 밖이나 중복 id가 나오면 1회 다시 요청하고, 그래도 실패하면 `out_of_candidates`(미확정)입니다.
  - Grok 호출이 실패하면 문제를 `error`로 둡니다.
- 그림자 Grok: job의 `shadow_grok=true`이면 다수결 사례에도 Grok을 불러 `role='shadow_judge'`로 저장만 하고 결정에는 쓰지 않습니다. 기본값은 파일럿 true, 그 외 false입니다.
- 사유 코드 §8: `unit_grok`, `concept_grok`, `two_models_only`, `insufficient_models`, `unit_tie`, `unit_low_conf`, `concept_low_conf`, `unit_hint_conflict`, `out_of_candidates`, `truncated`는 검토 필요(Y)입니다. `majority_2of3`, `candidate_fallback`은 정보용입니다. Y가 하나도 없으면 `auto`이고, 임계값은 `e2c.config`에 둡니다.
- 저장 §12
  - `model_call`에는 모든 호출을 추가만 하고 덮어쓰지 않습니다.
  - 같은 `input_hash`(problem.inputHash+stage+options+promptVersion+model)의 성공 호출이 있으면 다시 부르지 않고 재사용합니다.
  - `problem_result`는 문제당 1행입니다. status가 `overridden`, `confirmed`, `applied`인 행은 모든 재실행(`rerun_review` 포함)에서 바꾸지 않습니다.
  - 단원을 수동으로 바꾸면 개념 단계를 재실행 대상으로 표시하고, 이전 개념 결과는 이력에 남깁니다.
  - 저장 전에 주·보조 개념이 모두 `final_unit_id` 소속인지 코드로 검증합니다.
- 프롬프트 버전: `e2c-unit-v2`, `e2c-concept-v2`, `e2c-grok-unit-v2`, `e2c-grok-concept-v2`. 공통 system prompt는 고정 접두부로 둡니다.
- job
  - kind는 `pilot`, `run_all`, `run_ids`, `rerun_review`이고 mode는 `realtime`, `batch`입니다. 기본값은 `dry_run=true`입니다.
  - 모델별 세마포어는 `E2C_CONCURRENCY_*`(기본 4)입니다.
  - 진행할 때마다 `cursor_problem_id`를 저장해 서버가 재시작돼도 재개합니다. 러너 없이 running으로 남은 job은 `paused`로 바꿉니다(l2oJobs의 `reapOrphans` 방식).
  - 실행 중 누적 비용이 `E2C_BUDGET_USD`를 넘으면 `paused`로 바꿉니다.
  - batch 모드는 W1 단원 추출 → W2 다수결 없는 문제만 Grok 단원 → W3 개념 연동 → W4 다수결 없는 문제만 Grok 개념 순서입니다. 웨이브마다 부분 결과를 저장합니다. 실패 건은 다음 웨이브 전에 realtime으로 재시도하고, `xai_batch_ids`를 기록합니다. Claude·Gemini는 realtime 호출을 써도 됩니다.

### 검토 UI `/exam2concepts`
- 상단
  - 버튼: 파일럿 실행, 선택 문항 실행, 전체 실행(batch), 검토 필요 재실행.
  - 토글: dry-run, 그림자 Grok.
  - 진행 바, 누적 비용, Grok 호출 수.
  - 필터: 상태, 사유 코드, 결정 경로(majority/grok/manual), 과목, 연도.
- 좌우 행은 legacy2ontology와 같은 방식으로 맞춥니다.
- 좌측: 메타, 문제, S번호가 붙은 해답(MathView). 근거 단계를 클릭하면 해당 S행이 하이라이트됩니다.
- 우측
  - 단원: 모델별 관련 단원·확률·표(규칙), 집계(3/3·2/3·2/2·불일치), Grok 결과, 채택 단원과 결정 경로 배지.
  - 개념: 개념별 모델 표(주/보조·확신도), 집계, Grok 결과, 사유 코드 배지.
  - 수동 수정: 단원 선택, 주 1개·보조 ≤3 선택(채택 단원 개념만 고를 수 있음), 사유 입력. 저장하면 `manual_override`에 기록되고 `status='overridden'`, `*_decision_source='manual'`이 됩니다. 확인을 누르면 `confirmed`가 됩니다.
  - 파일럿 라벨 모드: `pilot_label`을 입력합니다.
- 키보드: J/K로 이동, Enter로 확인.

## API 계약
다른 프로젝트와 주고받는 것은 없습니다. 아래는 같은 앱 내부 계약이고 모두 로그인 세션이 필요합니다.
- `GET /api/e2c/problems?status=&reason=&source=&subject=&year=&page=&pageSize=` → `{ total, items: ProblemRowVM[] }`. 각 항목은 메타, 문제·해답, keySteps, 결과, 모델 호출 요약입니다.
- `POST /api/e2c/jobs` `{kind, mode, scope:{ids?:number[]}|{all:true}|{pilot:true}, dryRun, shadowGrok}` → `JobVM`. 이미 running인 job이 있으면 409를 돌려줍니다.
- `GET /api/e2c/jobs/active`, `GET /api/e2c/jobs/:id` → `JobVM`(processed, total, needsReview, failed, grokUnitCalls, grokConceptCalls, costUsd, status).
- `POST /api/e2c/jobs/:id/{pause|resume|cancel}` → `JobVM`.
- `POST /api/e2c/override` `{problemId, unitId?, primaryConceptId?, secondaryConceptIds?, reason}` → 갱신된 결과. 개념이 단원 밖이거나 보조가 3개를 넘으면 400입니다.
- `POST /api/e2c/confirm` `{problemId}` → status `confirmed`.
- `PUT /api/e2c/pilot-label` `{problemId, unitId, primaryConceptId, secondaryConceptIds}`.
- `POST /api/e2c/reports` `{jobRunId}` → `{path}`(reports/ 파일 생성).

## 수용 기준
1. `docs/e2c-schema.md`와 `docs/jev-api.md`가 있습니다. `web/src/lib/e2c/schema-names.ts` 밖의 e2c 코드에 MariaDB 기출 테이블·컬럼 이름 문자열이 나오지 않고, `<<`로 시작하는 placeholder가 남아 있지 않습니다.
2. e2c MariaDB 모듈은 SELECT 문만 쓰고, 연결마다 `SET SESSION TRANSACTION READ ONLY`를 실행합니다. INSERT, UPDATE, DELETE, ALTER가 없습니다(grep으로 확인).
3. 비밀값 하드코딩이 없고, `web/.env.example`에 e2c 변수 이름만 있습니다.
4. `npm run db:e2c`를 두 번 연속 실행해도 오류가 없고, `e2c` 스키마에 job_run, model_call, problem_result, manual_override, pilot_label, concept_option_text, config 테이블이 생깁니다.
5. `web/package.json`에 `test:e2c` 스크립트(`node --experimental-strip-types --test`)가 있고 통과합니다. 테스트는 최소한 아래 경우를 각각 확인합니다.
   - `pickFinalUnit`: 단일 최대(precedence), 선후 미연결 동률(curriculum_order), 과목 간 선후(앞 과목 단원 < 뒤 과목 단원), 사이클(`precedence_cycle`).
   - `tallyUnits`: 3/3, 2/3, 모두 다름, 2개 성공 일치, 2개 성공 불일치, 1개 성공, 0개 성공.
   - `tallyConcepts`: 주 다수결, 보조가 역할 무관 2표 이상일 때만 채택, 주 개념은 보조에서 제외, 3개 초과 시 정렬 규칙, 2개 성공 시 두 모델 공통만.
   - 사유 코드 계산: 각 코드와 `auto` 판정.
   - 전처리: S번호 분할, 40자 미만 skip, 6,000자 잘림과 truncated.
   - 해시 멱등: 같은 입력이면 같은 해시이고, 프롬프트 버전이 바뀌면 다른 해시입니다.
6. 어댑터 테스트는 `globalThis.fetch` 스텁(또는 의존성 주입)으로 JEV·Gemini·xAI를, SDK 주입으로 Claude를 대신합니다. 정상, 429 후 성공(Retry-After 존중), 스키마 위반 1회 재요청, 범위 밖 id, JEV 키 미설정(`not_configured`)을 확인합니다.
7. 파이프라인 테스트는 모델·DB를 대체한 상태에서 아래를 확인합니다.
   - 세 모델 단원 표가 2표 이상 일치하고 그림자가 꺼져 있으면 Grok 단원 호출이 0회입니다.
   - 세 표가 모두 다르면 Grok이 1회 호출되고 `unit_decision_source='grok'`, `unit_grok` 사유가 붙습니다.
   - JEV 미설정 + 나머지 두 모델 일치면 `two_models_only`, `needs_review`입니다.
   - 제안 모델 3개가 모두 실패하면 문제가 `error`이고 Grok 호출은 0회입니다.
   - 최종 결과는 단원이 정확히 1개, 주 개념이 1개, 보조가 ≤3개이고 모두 채택 단원 소속입니다.
8. 재실행 테스트: `overridden` 또는 `confirmed`인 문제를 다시 실행하면 `problem_result`는 그대로입니다. `rerun_review`에서도 새 호출은 `model_call`에만 추가됩니다. 이미 성공한 같은 `input_hash` 호출은 다시 부르지 않습니다.
9. 일시정지 후 재개하면 `cursor_problem_id` 다음 문제부터 처리하고, 누적 비용이 `E2C_BUDGET_USD`를 넘으면 job이 `paused`가 됩니다.
10. `POST /api/e2c/override`에 채택 단원 밖 개념을 넣거나 보조를 4개 넣으면 400입니다. 정상 요청이면 `manual_override` 행이 추가되고 `status='overridden'`, 해당 단계 decision_source가 `manual`이 됩니다.
11. `/exam2concepts` 페이지가 로그인 상태에서 열립니다. 문제·해답(S번호), 모델별 표, 집계, 결정 경로 배지, 사유 코드, 수동 수정 컨트롤이 보이고, 수동 수정의 개념 선택 목록에는 채택 단원 개념만 나옵니다.
12. 원문 §21 형식의 리포트 파일을 만드는 함수가 있고, 픽스처 데이터로 실행하면 `reports/e2c-<kind>-<date>.md`가 생깁니다.
13. `docs/COMPONENTS.md`에 새 페이지·컴포넌트·모듈·DDL·문서가 실제 경로로 등록돼 있습니다.
14. `web`에서 `npm run lint`, `npx tsc --noEmit`, `npm run test:l2o`, `npm run test:e2c`가 모두 통과합니다.

## 가정
- 환경변수는 기존 앱 이름을 재사용합니다. MariaDB는 `MARIADB_DSN`(카드의 `LEGACY_MARIADB_URL` 대신), KG는 `DATABASE_URL`(`KG_DATABASE_URL` 대신), JEV는 `JEV_API_URL`/`JEV_API_KEY`(없으면 `JEV_KEY`)입니다. e2c 고유 변수(`XAI_API_KEY`, `GROK_MODEL`, `GROK_REASONING_EFFORT`, `E2C_*`)는 새로 추가합니다.
- Claude 호출은 temperature 0 대신 기존 claudeSelector 방식(effort low, temperature 생략)을 씁니다. 현재 Sonnet 모델이 temperature를 거부하기 때문입니다.
- JEV는 기존 코드에 쓰이는 systemone choice API를 문서 확인된 엔드포인트로 보고 `docs/jev-api.md`에 정리합니다.
- 테스트는 msw·Playwright 대신 기존 `node --test` + fetch 스텁으로 하고, E2E는 수용 기준 11의 화면 확인으로 대신합니다.
- KG 반영(applied)은 이 카드 범위 밖입니다.
- 보조 개념 규칙과 needs_review 기준(2개 모델 일치·Grok 결정 모두 검토 필요)은 원문 기본값 그대로 두고 `e2c.config`로 바꿀 수 있게 합니다.
