# exam2concepts(e2c): 기출문제 → 단원 1개 → 개념 연동 (v1.1, 스키마 확정 + 비용 최소화판)

상세 원문은 `specs/exam_problems2concepts.md`(v1.1)입니다. 아래에 적지 않은 세부는 원문을 따릅니다(프롬프트 §11, JSON 스키마 §10, 비용 §15, 리포트 형식 §21). 이 문서와 원문이 다르면 **이 문서가 우선**합니다.

이번 판에서 바뀐 점:
1. 스키마 placeholder를 모두 확정했습니다. 구현할 때 DB에 접속해 다시 조사하지 않습니다.
2. 카드의 추가 요구를 넣었습니다. 이 작업은 기존 문제를 KG에 한 번 연동하고 끝나는 일(2026-11-28까지)이므로 AI API 비용을 최소로 써야 합니다. 이를 위해 "비용 최소화(캐싱·Batch)" 절을 새로 두었습니다.

## 배경과 목적
- 대상은 MariaDB 기출문제 `mathdb.question_units`(약 7,142문항, 읽기 전용)입니다. 문항마다 다음을 정합니다.
  - KG 2022 개정 교육과정의 단원 정확히 1개
  - 그 단원 안의 주 개념 1개
  - 보조 개념 0~3개
- 판단 입력은 `raw_statement`(문제)와 `raw_note_statement`(해답) 두 TEXT입니다.
- 단원은 이렇게 정합니다.
  1. JEV·Claude·Gemini가 각각 관련 단원 집합을 냅니다.
  2. 코드가 모델마다 `pickFinalUnit`(선후상 가장 뒤 단원)을 적용해 1표를 만듭니다.
  3. 2표 이상 일치하면 그 단원을 채택하고, 아니면 Grok이 정합니다.
- 개념은 이렇게 정합니다.
  1. 채택 단원의 개념만 후보로 둡니다.
  2. 세 모델이 각각 주 개념 1개와 보조 개념 0~3개를 냅니다.
  3. 주 개념이 2표 이상 일치하면 채택하고, 아니면 Grok이 정합니다.
- 사유 코드로 `auto`와 `needs_review`를 나눕니다. 검토 UI에서 수동으로 고칠 수 있고, 수정 이력이 남으며, 재실행해도 수정값을 덮어쓰지 않습니다.
- 단발성 작업이므로 같은 입력은 두 번 과금하지 않습니다. 고정 접두부는 프롬프트 캐시를 타게 하고, 전체 실행은 할인되는 Batch API로 보냅니다.
- 같은 앱 `web/`에 두고, 다음 두 파일과 나란히 놓습니다.
  - **Legacy2OntologyPage** `web/src/app/legacy2ontology/page.tsx`
  - **Legacy2OntologyClient** `web/src/components/l2o/Legacy2OntologyClient.tsx`

### 하지 않는 것
- MariaDB 쓰기, 스키마 변경, 문제·해답 본문 수정.
- KG 최종 반영(`applied` 버튼과 트랜잭션)과 문제→단원·개념 관계 생성. 사용자 승인 후 별도 카드에서 하고, 여기서는 `docs/e2c-schema.md`의 Open Question에만 남깁니다.
- legacy 문제–개념 연결 힌트 사용. 연결 테이블이 확인되지 않아 비활성으로 둡니다.
- 실제 유료 API로 파일럿이나 전체 실행을 하는 것, 배포, push, 운영 DB 반영.
- Gemini explicit cache(`cachedContents` 리소스)와 같이 저장 비용이 드는 캐시 객체 생성. 접두부 implicit/automatic 캐시만 씁니다.
- 개념 간 선후 작업, 단원·과목 선후 편집, `specs/math_concepts2ontology.md` 변경, legacy2ontology 동작 변경(기존 selectors 파일 포함).
- Playwright·msw 같은 새 테스트 프레임워크 도입. 기존 `node --test`를 씁니다.

## 확정 스키마 (`schema-names.ts`에 그대로 둠)
| Placeholder | 확정값 |
|---|---|
| PROBLEM_TABLE | `mathdb.question_units`(MariaDB). PK `id` int, 문제 `raw_statement` text, 해답 `raw_note_statement` text |
| PROBLEM_META_COLS | 아래 "메타 컬럼" 표 |
| LEGACY_PROBLEM_CONCEPT_TABLE | 없음(`null`). `legacyConceptHints=[]`, 버린 개수 0 |
| LEGACY_TO_REP_MAP | `l2o.dedupe_member` → `l2o.dedupe_group` → `l2o.migration_result.kg_concept_id`(`web/db/l2o-schema.sql`). 함수만 구현하고 호출하지 않습니다 |
| KG_SUBJECT | `kg.nodes` level 노드 category=과목(`L4-HCM1`, `L4-HCM2`, `L4-HALG`, `L4-HCAL1`, `L4-HCAL2`, `L4-HPS`, `L4-HGEO` 등 접두. 실제 값은 KG 조회 결과 사용) |
| KG_UNIT | **l2oUnits** `web/src/lib/server/l2oUnits.ts`의 `listUnits` 중 `L4-H*`(category=대단원). 순서는 `props.order`, 없으면 id 끝 번호 |
| KG_UNIT_PRECEDES | `kg.edges` `PREREQUISITE_OF`(단원 src→dst이면 src가 앞), `PREREQ_OF`(과목 src→dst이면 src가 앞, `web/src/lib/graphDb.ts`) |
| KG_CONCEPT / KG_CONCEPT_UNIT_EDGE | `kg.math_concepts`, `kg.concept_unit_edges`(`is_active=true`) |
| KG_CONCEPT_DEFINITION | 별도 필드 없음. 설명 첫 문장을 `e2c.concept_option_text`에 캐시(source=`auto`, 수동 수정은 `manual`) |
| KG_PROBLEM_LINK | 미정(Open Question) |

| apply_type | KG 과목 접두 |
|---|---|
| COMMON | `L4-HALG`, `L4-HCAL1` |

## 변경할 동작
### 기존 코드 재사용(필수)
- **MariaDB**
  - `e2cLegacyDb.ts`는 **legacyDb** `web/src/lib/server/legacyDb.ts`와 같은 방식으로 만듭니다.
  - 접속은 `MARIADB_DSN`을 쓰고, 연결마다 `SET SESSION TRANSACTION READ ONLY`를 실행하며, SELECT만 씁니다.
  - export는 `listProblemIds(filter)`, `getProblems(ids)`, `countProblems(filter)`입니다.
  - `stripHtml`과 `hwp-img-id` 규칙은 legacyDb의 것을 재사용합니다. 재사용을 위해 legacyDb에 export만 추가하는 것은 허용합니다.
- **KG**: **l2oPool** `web/src/lib/server/l2oPool.ts`의 `pool`을 씁니다.
- **임베딩**: **embedding** `web/src/lib/server/embedding.ts`의 `embedTexts`와 **l2oDedupeUtil** `web/src/lib/l2o/dedupe.ts`의 `cosine`을 씁니다. 결과는 아래 임베딩 캐시를 거칩니다.
- **HTTP**
  - **selectorCommon** `web/src/lib/server/selectors/common.ts`의 `postJson`, `HttpError`, `errorText`를 씁니다.
  - e2c 재시도는 `web/src/lib/e2c/retry.ts`에 둡니다. 대기는 1s→2s→4s→8s이고, 최대 5회이며, `Retry-After`가 있으면 그 값을 우선합니다.
  - 기존 `withRetry`는 바꾸지 않습니다.
- **Claude**: **claudeSelector** `web/src/lib/server/selectors/claude.ts` 방식을 따릅니다.
  - `@anthropic-ai/sdk` beta messages를 쓰고, `output_config.format` json_schema에 후보 enum을 주입하고, `effort: low`, server-side fallback을 씁니다.
  - temperature는 보내지 않습니다. max_tokens는 2000이고, refusal은 실패로 처리합니다.
  - 모델은 `CLAUDE_MODEL`, 없으면 `claude-sonnet-5-5`입니다.
  - SDK 클라이언트는 주입할 수 있게 만듭니다.
- **Gemini**: **geminiSelector** `web/src/lib/server/selectors/gemini.ts` 방식을 따릅니다.
  - generateContent에 `temperature: 0`, `responseMimeType: application/json`, `responseSchema`를 씁니다.
  - 모델은 `GEMINI_MODEL`, 없으면 `gemini-4-argon`입니다.
- **JEV**: **jevSelector** `web/src/lib/server/selectors/jev.ts`가 쓰는 TypeSafe System One API를 씁니다.
  - 엔드포인트는 `POST {JEV_API_URL}`(기본 `https://api.typesafe.ai/v1/systemone`)입니다. 다른 엔드포인트는 만들지 않습니다.
  - 요청: `{model, state, questions:{q:{type:'choice', instructions, criteria:{id:text}}}}`
  - 응답: `answers.q.{choice, confidence, probabilities}`
  - `JEV_API_KEY`(없으면 `JEV_KEY`)가 없으면 `error='not_configured'`입니다.
- **Grok**: xAI `https://api.x.ai/v1/chat/completions`를 씁니다.
  - `response_format: {type:'json_schema'}`, `reasoning_effort=GROK_REASONING_EFFORT`(기본 `low`), 모델 `GROK_MODEL`(기본 `grok-4.7`).
  - 비용은 `usage.cost_in_usd_ticks × 1e-10`입니다.
- **화면**: 수식은 **MathView** `web/src/components/MathView.tsx`로 그립니다. 진행 표시는 **JobProgress** `web/src/components/l2o/JobProgress.tsx` 패턴을 따릅니다. 인증은 legacy2ontology와 같은 세션 가드를 씁니다.
- **DB 없는 환경**: 모든 DB·모델 접근은 주입할 수 있는 저장소·어댑터 인터페이스 뒤에 둡니다. 테스트와 타입 검사는 DB 없이 통과해야 합니다.

### 비용 최소화(캐싱·Batch) — 이번 판에서 추가
1. **결과 캐시(재호출 0)**
   - `model_call.input_hash`가 같은 성공 호출이 있으면 재사용하고 API를 부르지 않습니다.
   - 해시 입력은 `problem.inputHash + stage + role + 정렬된 options id·text + promptVersion + model`입니다.
   - 재실행, 중단 후 재개, `rerun_review`, batch에서 realtime으로 넘어가는 재시도까지 모두 이 캐시를 먼저 확인합니다.
   - 다수결이 이미 정해진 문제는 Grok을 부르지 않습니다(그림자 제외).
   - 단원 결과가 확정되고 바뀌지 않았으면 단원 단계를 다시 부르지 않습니다.
2. **임베딩 캐시**
   - 새 테이블 `e2c.embedding_cache(text_hash text primary key, model text not null, vector jsonb not null, created_at timestamptz default now())`를 둡니다.
   - 단원 설명, 개념 option text, 문제 텍스트 임베딩을 `sha256(model+text)`로 저장합니다.
   - 캐시에 있으면 `embedTexts`를 부르지 않습니다.
   - 임베딩은 후보가 상한(단원 15, 개념 `E2C_MAX_CONCEPT_OPTIONS`)을 넘는 경우에만 계산합니다.
   - 호출할 때는 캐시에 없는 텍스트만 모아 한 번에 보냅니다.
3. **프롬프트 접두부 캐시**: `promptBuild.ts`는 메시지를 아래 순서로 만듭니다.
   - 순서: ① 고정 system(버전별로 바이트까지 동일) → ② 후보 options 블록(id 기준 교육과정 순으로 결정적 정렬, 같은 후보 집합이면 바이트까지 동일) → ③ 문제별 가변부(메타, 문제, S번호 해답).
   - Claude: ② 블록 끝에 `cache_control: {type:'ephemeral'}`를 둡니다. options가 없으면 ① 끝에 둡니다. 접두부가 모델의 최소 캐시 길이보다 짧으면 캐시가 걸리지 않을 뿐이고 오류는 아닙니다.
   - Gemini와 xAI: 같은 접두 순서를 지켜 implicit/automatic 캐시를 타게 합니다. 별도 캐시 객체는 만들지 않습니다.
   - 러너는 캐시 적중을 높이려고 처리 순서를 묶습니다. 단원 단계는 (후보 집합 해시, problemId) 순, 개념 단계는 (채택 단원, problemId) 순입니다. 그 묶음 안에서는 `cursor_problem_id` 재개 규칙을 지킵니다.
4. **사용량 기록**
   - `model_call`에 `cached_input_tokens int`, `cache_write_tokens int`, `batch_id text`, `batch_discount boolean default false` 컬럼을 더합니다.
   - 모델별로 읽는 위치는 다음과 같습니다.
     - Claude: `usage.cache_read_input_tokens`, `cache_creation_input_tokens`
     - Gemini: `usageMetadata.cachedContentTokenCount`
     - xAI: `usage.prompt_tokens_details.cached_tokens`
   - `cost.ts`는 모델별 단가표(`e2c.config` key `pricing`, 기본값은 원문 §15와 각 사 공식 요금)로 캐시 입력, 일반 입력, 출력, Batch 할인을 나눠 USD를 계산합니다.
   - xAI는 `cost_in_usd_ticks`가 있으면 그 값을 우선합니다.
5. **Batch 우선(전체 실행)**
   - `run_all`의 기본 mode는 `batch`입니다.
   - W1(단원 추출)과 W3(개념 연동)에서 Claude는 Anthropic Message Batches API, Gemini는 Gemini Batch API(inline requests), W2·W4의 Grok은 xAI Batch API를 씁니다. JEV는 Batch가 없으므로 realtime입니다.
   - batch 요청 id는 `problemId:stage:model:promptVersion`입니다.
   - 제출한 batch id는 `job_run.xai_batch_ids`와 새 컬럼 `job_run.batch_ids jsonb default '{}'`(모델별 배열)에 저장합니다. 서버가 재시작되면 이 id로 결과를 다시 받아 옵니다.
   - 이미 캐시에 성공 호출이 있는 문제는 batch에 넣지 않습니다.
   - batch가 실패하거나 만료된 건만 다음 웨이브 전에 realtime으로 다시 시도합니다.
   - 파일럿, `run_ids`, `rerun_review`의 기본 mode는 realtime입니다.
6. **출력·추론 토큰 억제**
   - Claude는 `effort: low`, Grok은 `reasoning_effort=low`를 기본으로 둡니다.
   - `reason`은 스키마 maxLength(300/500)를 그대로 씁니다.
   - 스키마 위반으로 다시 요청하는 것은 1회까지입니다.
7. **사전 추정과 상한**
   - job을 시작하기 전에 `cost.ts`가 다음 값으로 예상 비용을 계산해 `JobVM.estimatedCostUsd`로 돌려줍니다.
     - 대상 문항 수, 이미 캐시된 호출 수, 평균 문자 수(1자를 1토큰으로 셈), mode(Batch 할인 반영)
   - 예상 비용이 `E2C_BUDGET_USD`를 넘으면 시작 응답에 `budgetWarning=true`를 넣고, 사용자가 `force:true`로 다시 요청해야 시작합니다.
   - 실행 중 누적 비용이 상한을 넘으면 `paused`로 바꿉니다.
8. **그림자 Grok**: job의 `shadow_grok`이 true일 때만 부릅니다. 기본값은 pilot이면 `E2C_PILOT_SHADOW_GROK`(기본 true), 그 외는 false입니다. 화면 토글로 끌 수 있습니다.

### 파이프라인 규칙(원문 요점)
- **전처리**
  - `problemText = stripHtml(raw_statement)`, `solutionText = stripHtml(raw_note_statement)`입니다. backtick 수식은 그대로 둡니다.
  - 해답은 줄·문장 단위로 나눠 S1..Sn을 붙입니다.
  - 문제+해답이 40자 미만이면 `skipped_no_text`입니다. 이 문항은 모델을 부르지 않습니다.
  - 6,000자를 넘으면 keySteps 앞뒤를 우선 남기고 중략 표시를 넣으며 `truncated=true`로 둡니다.
  - `inputHash = sha256(problemText+solutionText+meta)`입니다.
- **후보 단원**
  - 과목 매핑으로 거르고, 15개를 넘으면 임베딩 상위 15개만 남깁니다.
  - 0개면 고등 전체로 넓히고 `candidate_fallback=true`입니다.
  - option text는 `과목 > 단원명 — 한 줄 설명`입니다.
  - 세 모델은 같은 목록을 받습니다. 후보가 0개면 호출하지 않습니다.
- **`pickFinalUnit`**
  - 단원 `PREREQUISITE_OF`와 과목 `PREREQ_OF`(앞 과목의 모든 단원 < 뒤 과목의 모든 단원)를 합친 그래프의 전이 폐쇄로 비교합니다.
  - 최대 원소가 1개면 `precedence`입니다.
  - 여러 개면 (과목 순서, 단원 순서)상 가장 뒤 단원이고 `curriculum_order`입니다.
  - 사이클이면 `error='precedence_cycle'`입니다.
  - 결정적이며 모델을 부르지 않습니다.
- **JEV 임계값**(`e2c.config`)
  - 관련 단원: 확률 ≥ 0.10인 단원입니다. 없으면 최고 확률 단원 1개입니다.
  - 보조 개념: 최고 확률 다음 순위 중 확률 ≥ 0.15인 것을 최대 3개 고릅니다.
- **집계**(원문 §6.1, §7.3)
  - 성공 모델 3개: 2표 이상 일치하면 majority, 아니면 Grok.
  - 성공 모델 2개: 일치하면 majority + `two_models_only`, 불일치하면 Grok.
  - 성공 모델 1개: Grok + `insufficient_models`.
  - 성공 모델 0개: `error`, Grok을 부르지 않습니다.
  - `not_configured`는 실패로 칩니다.
  - 보조 개념: 채택된 주 개념을 빼고, 역할과 관계없이 2개 이상 모델이 제안한 개념입니다. 3개를 넘으면 (제안 모델 수 desc, 평균 확신도 desc, conceptId asc) 순 상위 3개입니다. 성공 모델이 2개면 두 모델이 모두 제안한 개념입니다.
- **Grok**
  - 단원: 성공 모델의 관련 단원 합집합 안에서 `usedUnits`를 받고, 코드가 `pickFinalUnit`을 적용합니다.
  - 개념: 제안된 개념 합집합 안에서 주 1개 + 보조 ≤3개를 받습니다.
  - 성공 모델이 1개면 범위를 후보·options 전체로 넓힙니다.
  - 범위 밖이나 중복 id가 나오면 1회 다시 요청하고, 그래도 실패하면 `out_of_candidates`입니다.
  - Grok 호출이 실패하면 문제를 `error`로 둡니다.
- **사유 코드**
  - 검토 필요(Y): `unit_grok`, `concept_grok`, `two_models_only`, `insufficient_models`, `unit_tie`, `unit_low_conf`, `concept_low_conf`, `unit_hint_conflict`, `out_of_candidates`, `truncated`.
  - 정보용: `majority_2of3`, `candidate_fallback`.
  - Y가 없으면 `auto`입니다. 임계값(0.5/0.3/0.6)은 `e2c.config`에 둡니다.
- **저장**
  - `model_call`에는 추가만 합니다.
  - `problem_result`는 문제당 1행이고 `problem_id`는 `question_units.id`입니다.
  - `overridden`, `confirmed`, `applied`인 행은 어떤 재실행에서도 바꾸지 않습니다.
  - 단원을 수동으로 바꾸면 개념 단계를 재실행 대상으로 표시하고 이전 결과는 이력에 남깁니다.
  - 저장 전에 주·보조 개념이 모두 `final_unit_id` 소속인지 검증합니다.
- **프롬프트 버전**: `e2c-unit-v2`, `e2c-concept-v2`, `e2c-grok-unit-v2`, `e2c-grok-concept-v2`.
- **job**
  - kind는 `pilot`, `run_all`, `run_ids`, `rerun_review`이고 기본값은 `dry_run=true`입니다.
  - 모델별 세마포어는 `E2C_CONCURRENCY_*`(기본 4)입니다.
  - `cursor_problem_id`를 저장하고, 고아 running job은 `paused`로 바꿉니다(l2oJobs의 `reapOrphans` 방식).
  - pilot scope는 `apply_type`·연도·`difficulty_level`이 고르게 섞이도록 100~200문항을 시드 고정으로 뽑습니다.

## API 계약
다른 프로젝트와 주고받는 것은 없습니다. 아래는 같은 앱 내부 계약이고, 모두 로그인 세션이 필요합니다(없으면 401).
- `GET /api/e2c/problems?status=&reason=&source=&subject=&year=&page=&pageSize=` → `{ total, items: ProblemRowVM[] }`
- `POST /api/e2c/jobs` `{kind, mode?, scope:{ids:number[]}|{all:true}|{pilot:true}, dryRun, shadowGrok, force?}` → `JobVM`
  - mode를 생략하면 run_all은 batch, 나머지는 realtime입니다.
  - 이미 running인 job이 있으면 409입니다.
  - 예상 비용이 상한을 넘는데 force가 없으면 202 `{budgetWarning:true, estimatedCostUsd}`를 돌려주고 job을 시작하지 않습니다.
- `GET /api/e2c/jobs/active`, `GET /api/e2c/jobs/:id` → `JobVM`
  - 필드: `{id, kind, mode, status, processed, total, needsReview, failed, grokUnitCalls, grokConceptCalls, costUsd, estimatedCostUsd, cacheReusedCalls, cachedInputTokens, inputTokens}`
- `POST /api/e2c/jobs/:id/{pause|resume|cancel}` → `JobVM`
- `POST /api/e2c/override` `{problemId, unitId?, primaryConceptId?, secondaryConceptIds?, reason}` → 갱신된 결과. 단원 밖 개념이나 보조 4개 이상이면 400입니다.
- `POST /api/e2c/confirm` `{problemId}` → status `confirmed`
- `PUT /api/e2c/pilot-label` `{problemId, unitId, primaryConceptId, secondaryConceptIds}`
- `POST /api/e2c/reports` `{jobRunId}` → `{path}`

8. 어댑터 테스트(JEV·Gemini·xAI는 fetch 스텁, Claude는 SDK 주입)
   - 정상 응답.
   - 429 후 성공(Retry-After 존중).
   - 스키마 위반 시 1회 재요청.
   - 범위 밖 id.
   - JEV 키 미설정(`not_configured`).
   - xAI `cost_in_usd_ticks`의 USD 환산.
   - 각 사 응답의 캐시 토큰 필드가 `cached_input_tokens`(Claude는 `cache_write_tokens` 포함)로 정규화됩니다.
9. Batch 어댑터 테스트(스텁): Claude Message Batches, Gemini Batch, xAI Batch 각각에 대해 다음을 확인합니다.
   - 제출 요청에 `problemId:stage:model:promptVersion` id가 들어갑니다.
   - 결과를 받으면 id별로 `model_call`(batch_id, batch_discount=true)로 저장됩니다.
   - 실패하거나 만료된 항목만 realtime 재시도 목록에 들어갑니다.
   - 이미 결과 캐시가 있는 문제는 제출 목록에서 빠집니다.
10. 파이프라인 테스트(모델·DB 대체)
    - 2표 이상 일치하고 그림자가 꺼져 있으면 Grok 호출이 0회입니다.
    - 세 표가 모두 다르면 Grok 단원 호출이 1회이고, `unit_decision_source='grok'`이며 `unit_grok` 사유가 붙습니다.
    - JEV 미설정이고 두 모델이 일치하면 `two_models_only`, `needs_review`입니다.
    - 세 모델이 모두 실패하면 `error`이고 Grok 호출은 0회입니다.
    - 최종 결과는 단원 1개, 주 개념 1개, 보조 ≤3개이고 모두 채택 단원 소속입니다.
    - `skipped_no_text` 문항은 모델 호출이 0회입니다.
11. 캐시 재사용 테스트
    - 같은 문항 집합으로 job을 두 번 실행하면 두 번째 실행의 모델 API 호출(어댑터 스텁 호출 수)이 0회이고, 임베딩 호출도 0회입니다.
    - 프롬프트 버전 하나를 바꾸면 그 단계만 다시 호출됩니다.
12. 재실행 테스트
    - `overridden`·`confirmed` 문제는 재실행 후에도 `problem_result`가 그대로입니다.
    - `rerun_review`의 새 호출은 `model_call`에만 추가됩니다.
13. job 테스트
    - 일시정지 후 재개하면 `cursor_problem_id` 다음 문제부터 처리합니다.
    - 누적 비용이 `E2C_BUDGET_USD`를 넘으면 `paused`가 됩니다.
    - 예상 비용이 상한을 넘으면 force 없는 시작 요청이 job을 만들지 않고 `budgetWarning:true`를 돌려줍니다.
    - `run_all`의 기본 mode는 batch입니다.
14. override 테스트
    - 단원 밖 개념이나 보조 4개를 넣으면 400입니다.
    - 정상 요청이면 `manual_override` 행이 추가되고, `status='overridden'`, 해당 decision_source가 `manual`이 됩니다.
15. `/exam2concepts`가 로그인 상태에서 열립니다. 문제·해답(S번호), 모델별 표, 집계, 결정 경로 배지, 사유 코드, 수동 수정 컨트롤, 누적·예상 비용, 캐시 적중률이 보입니다. 개념 선택 목록에는 채택 단원 개념만 나옵니다.
16. 픽스처로 리포트 함수를 실행하면 `reports/e2c-<kind>-<date>.md`가 생깁니다. 리포트에는 원문 §21 항목과 함께 다음이 들어갑니다.
    - 모델별 결과 캐시 재사용 건수
    - 캐시 입력 토큰 비율
    - Batch 처리 건수
    - Batch·캐시로 줄인 추정 금액
17. `docs/COMPONENTS.md`에 새 페이지·컴포넌트·모듈·DDL·문서가 실제 경로로 등록돼 있습니다.
18. `web`에서 `npm run lint`, `npx tsc --noEmit`, `npm run test:l2o`, `npm run test:e2c`가 DB 접속 없이 모두 통과합니다.

## 가정
- 기출문제는 `mathdb.question_units`(PK `id`, 문제 `raw_statement`, 해답 `raw_note_statement`)이고, 대상은 `subject_type='MATH' AND is_on=1`입니다.
- 시험 종류는 subscriber와 release_month로 추정합니다.
- legacy 문제–개념 연결 테이블이 없어 힌트는 비활성입니다.
- 선후 방향은 PREREQUISITE_OF·PREREQ_OF 모두 src가 앞입니다.
- 과목 매핑은 기본값이고 `e2c.config`에서 바꿀 수 있습니다.
- 환경변수는 기존 `MARIADB_DSN`, `DATABASE_URL`, `JEV_API_URL`, `JEV_API_KEY`/`JEV_KEY`를 재사용합니다.
- "최소 비용"은 결과·임베딩 캐시, 고정 접두부 프롬프트 캐시, 전체 실행의 각 사 Batch API(할인 요금), 저추론 설정, 사전 비용 추정으로 구현합니다.
- Gemini explicit cache 객체는 저장 비용이 들어 쓰지 않습니다.
- 2026-11-28 기한의 단발성 작업이므로 범용화나 장기 운영 기능은 넣지 않습니다.
- Claude는 temperature 없이 effort low를 씁니다. 테스트는 node --test와 스텁으로 하고, 화면은 KaTeX MathView로 그립니다.
- KG 최종 반영과 실제 유료 실행은 범위 밖입니다.
- Open Question(보조 규칙, needs_review 기준, 임계값)은 원문 기본값으로 구현하고 `e2c.config`에서 바꿀 수 있게 합니다.
