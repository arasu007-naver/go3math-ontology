## 배경과 목적
프로젝트 안의 컴포넌트 이름을 하나로 정해 두면 단축키처럼 쓸 수 있습니다. 사람이 프롬프트에서 이름만 말해도 task agent가 해당 파일을 바로 찾게 하는 것이 목적입니다. ontology(Ontology 웹, /Users/jaesung/QoollaWorkspace/go3math-ontology)의 공용 컴포넌트를 `컴포넌트명: 파일경로` 형식의 용어집으로 정리합니다.

## 범위
### 하는 것
- 저장소 루트에 `docs/COMPONENTS.md`를 새로 만듭니다.
- 다음을 뽑아 정리합니다.
  - 앱 진입점
  - 페이지/화면
  - 공용 UI 컴포넌트
  - 그래프 시각화 모듈
  - 데이터(온톨로지/챕터) 정의 파일
  - 상태 관리
  - API 클라이언트
  - 공용 유틸
- 기존 스펙 문서(DESIGN.md, agent-spec.md, level-spec.md, spec-level-1.md 등)도 '문서' 범주로 적습니다.
- 루트에 `CLAUDE.md`를 만들고, 용어집 참조와 갱신 규칙을 적습니다.

### 하지 않는 것
- 코드와 기존 문서 변경은 하지 않습니다.
- node_modules와 빌드 산출물은 넣지 않습니다.

## 변경할 동작
1. 맨 위에 사용법 단락을 두고, 범주별 절로 나눕니다: 진입점 / 페이지 / 공용 UI / 시각화 / 데이터 / 상태 / API / 유틸 / 문서.
2. 항목 형식은 `- **컴포넌트명**: \`상대경로\``입니다. 선택으로 별칭과 한 줄 설명을 붙입니다.
3. 컴포넌트명은 export 이름을 씁니다. 문서는 파일 제목을 씁니다.

## 수용 기준
- `docs/COMPONENTS.md`가 있고, 모든 항목이 `- **이름**: \`경로\`` 형식이다.
- 적힌 경로는 모두 실제로 존재한다.
- 이름과 별칭이 중복되지 않는다.
- 앱 진입점이 실려 있다.
- 루트의 기존 스펙 md 파일이 모두 '문서' 범주에 실려 있다.
- 코드가 없는 범주는 '해당 없음'으로 표기되어 있다.
- node_modules와 빌드 산출물 경로가 없다.
- 루트 `CLAUDE.md`에 용어집 참조와 갱신 규칙이 있다.
- 위 두 파일 외의 파일은 바뀌지 않았다.
